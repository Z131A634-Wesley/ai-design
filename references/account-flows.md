# 账户流程：登录、注册、验证、恢复

适用于账户界面、体验评审和模拟原型。仅使用产品实际支持的登录方式；生产认证、会话与权限由现有服务实现，不能用前端演示逻辑代替。

| 页面模式 | 适合 | 取舍 |
|---|---|---|
| 单列纯表单 | 登录频繁、工具型产品、手机 | 主动作紧邻字段；帮助入口不藏在页尾 |
| 品牌分栏 | 新用户较多，且素材可信、有品牌价值 | 手机收为单列，装饰移到次要位置或省略，不挤压表单 |
| 在任务中继续 | 预订、结账或会话过期 | 告知登录后回到哪里；保留允许保存的非敏感任务数据 |
| 账号优先分流 | 企业多组织、SSO 与密码并存且确需分流 | 用户可返回改账号；不透露账号存在性；同一认证方式无须拆两步 |

## 高保真落地

先把品牌、标题、说明、字段、主提交和帮助排成可扫读的一列；宽屏分栏的素材必须服务产品识别，不能只为填满另一半。用相同的内容列宽和对齐线串起登录、验证、找回；错误展开时不遮住帮助或提交。移动端先做正常、长错误与键盘打开三种画面。演示控制与产品表单分区，不能和主按钮同权重。

## 最小流程与状态

- 登录：输入 → 提交中 → 成功/必要验证 → 返回预期页面。区分字段未填/格式错、认证未通过、网络或服务故障。格式错误关联到字段；凭据失败用中性提示和恢复入口，不提示是账号还是密码错。网络失败保留可安全保留的输入，提供重试。不要保存密码或验证码到客户端持久化。
- 注册：仅收集必要信息；若需验证，说明验证渠道、下一步与返回方式。找回：显示中性确认、可回登录；重置链接过期给重新发送入口。SSO 或通行密钥仅在真实能力支持时出现。
- OTP/MFA：说明发往哪里（必要时脱敏）、验证码过期、重发倒计时、改渠道或备选方法。若视觉分格，仍应支持粘贴整串和自动填充。后台/原型使用明确标注的测试数据，不采集真实凭据。

## 组件与验收

- Web：持久可见标签；账号/密码使用合适的 `autocomplete`（如 `username`、`current-password`、`new-password`、`one-time-code`），不屏蔽密码管理器或粘贴；密码默认隐藏，显示/隐藏按钮有可访问名且不提交表单。
- 提交时避免重复发送，反馈清晰；键盘能到达恢复入口，提交失败后焦点到错误汇总、出错字段或与当前组件模式一致的位置。手机键盘弹起时能到达提交与错误提示。
- 实测（按适用性）：成功、无效输入、凭据失败、找回返回、验证码整串粘贴、键盘提交、宽/窄版；后端、验证码发送或密码管理器未接入时标记未验证。

参考：[Carbon Login](https://www.carbondesignsystem.com/building-blocks/core/patterns/login)、[GOV.UK Password input](https://design-system.service.gov.uk/components/password-input/)、[WCAG 2.2 可访问认证](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html)。规则为本地独立整理。
