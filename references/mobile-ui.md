# 移动端：平台差异与页面模式

先确认目标是原生、跨端实现、微信小程序，还是浏览器 H5。React Native/Flutter 不代表两端应做成同一套导航。浏览器模拟也不是原生运行或真机验证。

| 决策 | iOS/iPadOS | Android | 微信小程序 | H5 |
|---|---|---|---|---|
| 顶级导航 | 系统 tab/自适应侧栏；顶层目的地不是操作按钮 | Material 3 导航栏/rail 等随窗口变化 | 项目启用的原生 tabBar 或约定组件；勿与业务操作混用 | 简单页可单导航；多目的地产品按需底栏，不模拟系统栏 |
| 子页和返回 | 系统堆栈与返回手势；大窗口可分栏 | 系统返回/预测性返回，处理详情、浮层、根页 | 遵守宿主路由与返回，明确分享进入无上一页的落点 | 保留浏览器 Back；页面内返回与历史一致；深链有兜底 |
| 系统占用区域 | 按设备实际 safe area 布局，不能按固定刘海高度定位 | 使用 WindowInsets 分开处理系统栏、手势区和键盘 | 尊重胶囊与宿主栏，占位取平台/框架数据 | 全屏场景才按需使用 safe-area inset；吸底控件验浏览器栏与键盘 |
| 字号与触控 | 使用平台语义字体，核 Dynamic Type；常规触控推荐参考 44pt | 使用可随系统放大的文字单位；常规触控推荐参考 48dp | 按宿主和组件基线验触屏，不把 rpx 当 pt/dp | 保持可缩放；WCAG CSS px 条件按 Web 规范核对 |
| 手势与输入 | 保留系统返回；长按/滑动有可发现替代入口 | 不抢系统返回与边缘手势；测试 IME 显隐 | 不阻断宿主返回；贴底控件兼顾键盘 | 不以 hover 或手势为唯一入口；验页面滚动与键盘抬起 |
| 状态与恢复 | 权限拒绝、离线、深链、后台恢复按真实功能验证 | 同左；系统返回后检查已有输入/选择 | 区分宿主授权和业务错误；从分享回流可定位 | 区分页面加载失败与业务失败；恢复/重试按实际能力呈现 |

## 页面模式怎么选

- 列表—详情：窄屏保证列表和详情都有明确落点，返回恢复筛选、滚动与合理焦点；大窗可并排但保持同一信息结构。
- 主任务/表单：先确定内容与主操作的关系；只在长任务有收益时吸底，避免遮盖字段错误或键盘后的最后一行；可滚动到操作并提供清晰取消方式。
- 覆盖层：短、可中断的选择可用系统 sheet；长流程、需要保留路径或多字段编辑时优先独立屏。不把系统权限请求做成假的可交互系统弹窗。
- 首次引导：能直接体验就别挡先；权限在功能需要时说明用途，请求被拒绝仍给可行退路。离线只展示实际可离线使用的功能和数据范围。

## 高保真落地

选同平台、同任务的参考，确认真实屏幕中谁占空间：顶栏给定位，正文给内容，底部只在任务需要时放主要操作。列表先确定一行的信息优先级（对象、状态、关键区别）；详情承接相同名称、缩略图或状态，再展开内容，不把详情做成缩小的官网首屏。对照正常、空态、详情以及返回后的画面；模拟系统区域时明确它只代表布局，不伪装成系统功能。

## 验收

至少走一次主任务、返回和一条失败恢复；验证窄屏、字号放大、键盘、固定区、必要的横屏/平板与方向变化。原生走对应模拟器或真机并区分报告；Web 原型检查浏览器宽度与交互，不宣称已验证 VoiceOver/TalkBack、系统权限、安全区或真机手势。

参考：[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/)、[Android 自适应列表—详情](https://developer.android.com/develop/ui/compose/layouts/adaptive/list-detail?hl=en)、[Android Insets](https://developer.android.com/develop/ui/compose/system/insets)、[微信小程序设计指南](https://developers.weixin.qq.com/miniprogram/design/)、[WeUI](https://github.com/Tencent/weui)。平台样式随版本变动，不复制尺寸矩阵作永久合同。
