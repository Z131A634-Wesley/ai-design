# 交互与体验：状态、反馈、可操作

## 状态按行为选，不凑数

组件先定义作用、可访问名称、输入方式、状态、系统反馈与焦点去向。优先原生控件或项目已有的可访问组件；Web 键盘遵守对应 APG 模式，原生使用平台语义。无关状态标 N/A。

| 状态 | 做什么 |
|---|---|
| 默认、悬停、按压 | 默认用 token；悬停仅增强，不是唯一信息入口；触屏需要明确按下反馈 |
| 焦点、选中、展开 | 焦点与选中可区分；优先原生语义；需要时同步 `aria-expanded` 等，不让 CSS 或 ARIA 单独成为业务状态 |
| 禁用、只读、无权限 | 在恰当位置交代理由；原生不可用控件用 `disabled`，需保留可发现性的模式可用 `aria-disabled` 并阻止操作；不要求同时使用 |
| 加载、刷新 | 保持原操作可识别；防重复，长等待可提供进度或支持时取消；既有数据显示期间可保留并标刷新状态，不假造进度 |
| 空、失败、成功 | 区分首次为空、筛选无匹配与加载失败；给可行下一步；成功说明发生了什么。按模式选择非抢焦点状态播报或需立即处理的错误反馈 |

## 表单和焦点

- 标签始终可见，优先原生验证语义和适合的输入类型。提交时揭示相关错误，不让输入途中不断报错；错误关联字段，不靠颜色。长表单可加可聚焦的错误汇总和跳转；与字段旁文案一致。
- 保留非敏感填值，错误文案同时说出影响与可行下一步；同一操作用词一致（「发布」→「已发布」）。只提供实际支持的重试方式，不暴露内部错误或把请求 ID 当作唯一解释。
- Tab 在控件或复合组件间移动；菜单、标签组等内部用模式定义的方向键。按钮/链接尊重各自原生键盘语义，不给原生控件重复绑处理器。不用正 `tabindex` 补布局问题。
- 弹层按类型管理进入与退出焦点；模态内限制焦点，关闭后回触发者或合理后继；删除一行后回附近可继续操作的位置。吸顶/吸底不遮挡焦点；必要时提供 skip link。
- 区分通用规则与库行为：特定 Radix 组件依靠动画保留退出生命周期，不能推导为所有 CSS transition 都失效。按所用库/原生控件文档验证退出、减少动效、焦点及可访问名称。

## 锚定浮层

菜单、选择器和气泡按需要写清触发器、对齐、宽度策略、碰到可用边缘时的位移或换边，以及内容超高时的滚动区域。使用已有组件的定位和焦点能力；缩放起点跟随实际出现的一侧。验收屏幕边缘、滚动及项目实际存在的「模态框内再打开选择器」路径。悬停提示允许指针从触发器移动到提示内容，关键内容有键盘或触屏可达的入口。

## 红旗

- 错误只有红框；图标按钮无可访问名；替换原生控件但没有键盘支持；Tab 跳入隐藏区域；滚动后焦点被遮挡。
- 条件区块更新却不提示，或每次输入都播报整个页面；关闭/删除后焦点丢失；筛选为空被误报成数据丢失。
- 所有加载都锁全屏；操作按钮视觉反馈改变布局；把未提交、请求失败和成功画成一样。
