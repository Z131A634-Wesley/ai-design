# 原型：先验证流程，再提高保真度

1. 写目标：「谁在什么情境下完成什么」，再写可观察成功条件和本轮不做的事。
2. 画结构：入口、页面/浮层清单、当前状态、主动作和目的地；对复杂流程画线框流，让读者看到按钮位置与下一屏，不只看节点名。
3. 加关键分支：选一条频发失败或返回路径，定义状态保留、重试、退出和恢复；必要时覆盖无权限、离线或空态。不要为每个控件硬造九个状态。
4. 选最低够用的保真度：信息架构用线框；要验证可发现性、返回和反馈才做可点击原型；要比较字体/风格再做高保真。界面原型可用本地 HTML 或项目已有工具，不要求安装 Figma/Penpot 或建设生产应用。
5. 从明确入口实走脚本：让一位不知道实现的人尝试更好；无人测试则明确是自测。记录第一处犹豫、错误路径是否可回、哪些动作只是模拟。若要求只产出线框，到第 2–3 步停。

每条交互至少写 `当前界面／触发点／条件 → 下一个状态或界面／系统反馈／返回保留内容`。每个区域单独测试一次宽度适配和键盘/触屏可达性；不能实际运行时说明原因。原型使用虚构数据并标明边界，不接真实支付、认证或敏感数据，不自称原生验证。

用户要展示产品观感、比较方向或明确要求高保真时，按 [视觉方法](visual-craft.md) 选参考并审阅实际画面；高保真不等于接入真实服务，低保真也不用伪装成成品。用同一条任务路径检验布局和交互，不只交一张无法走通的首页。

参考：[NN/g Wireflows](https://www.nngroup.com/articles/wireflows/)、[Penpot Prototyping](https://help.penpot.app/user-guide/prototyping-testing/prototyping/)。
