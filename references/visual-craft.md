# 视觉设计方法：取材、选型、落地、复审

用于新设计、视觉改版、高保真原型和视觉评审。局部修样式不必走全套。先拿到真实标题、表单和数据，或明确哪些是示例；设计不是给占位内容套皮。

## 1 · 取材：用三个问题选参考

- **风格**决定观感：看字体角色、主次对比、网格、边距、图像裁切和表面层级；优先项目已有页面、用户参考或 Refero Styles。
- **界面**决定同一屏如何组织：对照真正同类的官网首屏、认证表单、任务列表、设置页；不看营销页来推导权限界面。
- **流程**决定状态如何接续：看错误、返回、恢复、确认、权限或离线场景。流程设计可从官方模式入手，不必先挑配色。

按 [来源地图](source-map.md) 找到相关参考。一个主参考建立视觉方向，辅参考只解决具名问题。记录 `案例/页面 → 看到的决定 → 本项目如何用 → 不借什么`。例如「窄列标签与控件左缘一致 → 登录与找回共用同一基线；不借品牌颜色」。反例：「参考苹果，做高级一点」。没看见画面时标注仅核对了文字；不复制原图或编造参考。

## 2 · 定方向：一页的视觉决定能落实到代码

- **两条有实质差异的候选**：方向开放的新产品或改版，比较焦点、构图与媒介。可用线框、文字结构或高保真稿，取得确认仅在用户要求时是必需的。已有品牌只比较布局内的可行变化。选定之后不要用两套各一半凑成结果。
- **写简短方向卡**：写清主任务、主视觉锚点、画面第一/第二阅读顺序、标题/正文/数据的字阶与对齐线、背景/正文/操作/状态色的职责、素材出处与移动裁切。亮点可以是排版、真实产品信息、编辑式图像或交互；后台的亮点也可以是异常处理一眼可见，不一定是特效。
- **做一次反模板复审**：只换项目名字能否用于另一个行业？有没有素材、构图或文字实际承载这个产品的特征？移除没有信息用途的标签、阴影和装饰；保留有理由的常规做法。紫色、圆角、系统字体不是天然错误。

## 3 · 实现：素材与类型先到位，再选效果

| 场景 | 更值得比较的两种方案 | 首次实现必须能看见 |
|---|---|---|
| 品牌官网 | 真实图像/空间主导 vs 字体/产品证明主导 | 第一屏有对象、价值与行动；用有意义的构图配真实物料；无合适图改用排版或原创图形，不伪造场所与产品 |
| 登录 / 账户 | 同轴单栏 vs 品牌分栏 | 表单形成一条明确阅读线；帮助与恢复不抢主动作；失败和找回仍保持品牌、列宽与层级；手机优先保主任务 |
| SaaS / 后台 | 密度较高的表格工作区 vs 聚焦当前项的列表—详情 | 先呈现能行动的信息；列与摘要对齐、状态能扫读；过滤、选中、错误不会把布局冲散 |
| 手机 App | 内容优先的图文列表 vs 动作优先的紧凑列表 | 顶栏、内容和底区各有职责；一屏有明确视觉层级；详情标题、主动作与返回承接列表上下文 |
| 可点击原型 | 低保真状态流 vs 高保真视觉稿 | 低保真验决策与状态；高保真把真实排版、组件、素材与关键状态一起做，不把模拟后端当作粗糙屏幕的理由 |

对照系统检查字体层级、实际断行、边缘对齐、组内/组间节奏、图片比例和可读性。先把静态版做成立，再添能说明反馈、变化或叙事的动效；按 [风格与效果取舍](style-direction.md) 选择预算与减少动效回退。

## 4 · 评审：先 Critique，再 Audit

- **视觉 Critique**：看实际成品与方向卡对照。先扫一眼能否找到主任务；逐项确认对齐、字阶、空白、密度、素材（有没有假 UI/空视觉）、品牌一致性、小屏重排。问题写成「证据 → 对体验的影响 → 改哪个元素」，至少复查一次实际修订；已经符合就说明具体证据，不编造缺陷。
- **交互/技术 Audit**：另查焦点、对比度和目标尺寸、正确状态、性能及适配。严重度按阻断、重要、打磨报告，不用检查数替代设计判断。没有真实渲染环境就明确落下哪项；能看图则截图后实际打开检查，不用 DOM 结果冒充观感。
