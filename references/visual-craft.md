# 视觉诊断

先看目标用户的真实任务、已有成品和素材，再看用户指定参考。参考的价值来自可验证的决定，例如「所有任务列共用同一对齐线，状态与负责人紧邻」或「标题靠左，右侧给可操作的产品证明」。记录“看见的特征 → 本项目的具体做法”，同时确认可用资产与使用权。

高保真或复杂新页面，以一个能代表设计难点的区域校准。先读清参考中的版式、真实内容、媒体裁切、控件和关键状态；整页缩略图看不清时补看局部。方案确认后先实现代表区域并对照，再推广共享规则。官网可用标题、主图及行动，工作区可用表头、选中行和详情，移动端可用一条主任务及其失败状态。内容页用真实长标题和缺图情况试排，验证主次、图片比例和回退。

- **运营/读取**：用对齐、密度、文字层级和例外组织页面。界面更像任务工作区时，不需要营销主视觉。高频控件的间距、视觉优先级和反馈比增加装饰重要。
- **品牌/说服**：以一条具体价值主张和一项产品证据构成画面。选择一个可记住的构图、版式或真实素材，把其余元素降权。保留有用的留白节奏。
- **防止套版**：把行业和产品名遮掉。如果标题、信息与画面仍能给其他行业使用，换上该产品特有的任务或证据，再修构图。优先消除重复框、无意义标签、无内容的大图和抢主次的色块。
- **复审截图**：打开宽、窄和关键状态，检查眼睛先到哪里、字阶与对齐、留白与密度、素材裁切、内容是否被盖。记录「证据 → 影响 → 应修改的层」，区分 token、共享控件、局部用法和设计规格；修后复看。[验收手册](quality-gates.md) 另查键盘、对比、溢出和真实交互。

方向选择、开工与变更确认规则见 [Skill 入口](../SKILL.md)；主方法由 [外部设计 Skill 调用](external-design.md) 指定。还缺真实视觉参考或需要解决特定视觉问题时，按 [来源地图](source-map.md) 取材。
