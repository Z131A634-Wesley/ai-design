# 质量闸门：按交付物选择证据

## 最低验证要求

| 交付物 | 实际检查 | 不要求 |
|---|---|---|
| 评审、规范 | 现有界面/文件证据、冲突、可执行改进；按阻断/重要/打磨分级 | 未请求的改动、新规范文件 |
| 线框、流程 | 入口与完成路径闭合；核对关键失败、返回和输入保留；对照平台惯例 | 构建、浏览器或视觉像素验收 |
| 可点击原型 | 走主路径和至少一条相关失败/返回；目标视口实渲染、主要动作可达，标出模拟边界 | 真实认证、支付、生产运行或未执行的真机验证 |
| 局部实现 | 只验证受影响的状态、设计一致性和已有相关测试；有布局变化就看受影响视口 | 重写规范、构建额外样本、统一套多断点 |
| 单页/多页实现 | 运行项目已有的相关构建、类型、lint 和测试；实际操作主流程；看代表性的宽/窄和真实变形点，按范围增加主题/设备 | 未采用的工具链及固定数量的截图 |

## 高保真与成品的视觉闸门

- 与选定的方向卡、参考和已有界面并排审视实际首屏/主屏；验证各级字号与权重、对齐线、素材及裁切、区块节奏、正常与关键失败状态、可读性。至少核对目标窄屏并抽查布局变化点。改版保留同视口的前后对照。
- 视觉不达标时指出具体控件、段落或区域和影响，修最影响任务和观感的一处，再看修订结果。例如「失败时错误和辅助链接挤到一行，拆到字段下方并维持表单基线」，而不是「再高级点」。
- 低保真只验信息和状态，高保真不能以「只是原型」免除视觉验收；模拟 DOM、脚本或静态检查不计作真实渲染或视觉复审。

## 运行时怎么查

- Web/H5：用项目现有浏览器工具（可用时调用 Playwright）。在宽/窄视口检查溢出、截断、层级、遮挡、失效链接、无效操作；用长标题和实际数据压力测试。截图应打开检查；记录浏览器、视口和路径。没有浏览器则静态检查并标未验证，不把静态扫描叫视觉通过。
- 移动端：如果实现是原生，用实际构建、模拟器或真机。验返回、手势替代、系统栏与键盘、字号、相关权限或恢复；按可用条件选择小屏/大屏及平板。浏览器仅能验证 Web/H5 或模拟原型。
- 交互：按场景走键盘、触屏、提交/返回、失败重试。若用 axe 或等价扫描，补人工检查焦点顺序、遮挡、读屏反馈、图像/渐变上的文字和拖拽替代；自动扫描不等于合规。
- 内容与性能：发布界面不得把假地址、评价、指标当事实；示例明确标注模拟。按用途检查资源失败、图像跳动和动效，影响明显才加测性能。优先用已有检查工具；新增依赖或访问受限环境按项目与用户约束处理。

## Web 无障碍基线

- WCAG 2.2 文本 AA：普通文本 ≥4.5:1；大字（至少 18pt，或至少 14pt 粗体）≥3:1。传递必要状态或识别控件所需的非文本信息按 1.4.11 核对 ≥3:1，注意条款例外。
- 2.5.8 AA 目标尺寸 24×24 CSS px，有间距等例外；主要触屏目标可优先按产品条件做到 44×44 CSS px。不要把产品建议或原生 pt/dp 写成 WCAG 的 CSS px 要求。
- AA 要有可见焦点且不被作者内容完全遮住；产品目标是不被遮挡。焦点外观 2.4.13 是 AAA；减少交互动效是良好默认，2.3.3 是 AAA。4.1.1 Parsing 已在 WCAG 2.2 移除。

## 交付记录

只报相关项：**通过 / 失败 / 未验证 / 不适用**，附命令、路径或观察结果。优先修复影响主任务或可访问性的失败；如无法继续，注明遗留问题。原型和生产验证分别记录。
