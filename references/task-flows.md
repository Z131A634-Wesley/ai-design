# 多步骤操作：引导、申请、预约、结账

- 先定用户是否必须走这条路：首次引导能跳过就允许跳过；短任务不要无故拆步，长任务按用户心智、依赖和风险分组。
- 每一步有明确标题、完成条件和可见下一步；步骤稳定、对当前进度有帮助时显示进度；条件分支不要承诺错误的总步数。说清必填内容与预计影响，默认不重复询问已给出的信息。
- 返回/前进不丢普通填值；改变上游选择后，只作废依赖结果并告知。高成本任务优先考虑草稿与恢复，但敏感内容不要不加区别地存储。
- 有实际承诺、付款或不可逆提交时，给确认页：列关键资料、金额/限制和可编辑项；返回编辑后回确认页，不强制走完剩余流程。确认与实际执行不同，避免用成功样式显示还没提交的步骤。
- 提交中防重复；失败说清可安全重试还是可能已提交、如何确认，保留可安全保留的输入；完成页提供下一步和可用凭据。取消/退出说清会丢失什么。
- 验收：完成全路径、上一页与改一项返回、校验失败、异步失败/重试；涉及中断时另验恢复和离开确认。原型只模拟提交，明确不产生真实订单或数据。

参考：[GOV.UK Check answers](https://design-system.service.gov.uk/patterns/check-answers/)、[GOV.UK Validation](https://design-system.service.gov.uk/patterns/validation/)；改写为项目无关规则。
