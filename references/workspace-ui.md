# Web App 与工具：把空间给主任务

先说清楚用户是要「输入并得到结果」「连续编辑」「比较与处理」，还是「浏览或标注素材」。用一个实际任务填画面。营销、登录和帮助是别的页面职责；工作界面可承接相同品牌语言。

| 任务 | 布局起点 | 缩窄和状态 |
|---|---|---|
| 转换、查询、计算、生成 | 一列输入与主操作，结果紧随其后；确实需要反复对照时，宽屏才把输入和输出并排。 | 窄屏先输入后结果，提交后给可感知的反馈；重试保留输入。区分尚未运行、运行中、失败、成功及修改输入后的旧结果。 |
| 文档、画布、代码或媒体编辑 | 打开的对象和保存状态放顶栏，高频工具靠近编辑区，画布或文档占主要面积。资源列表和检查器各按需要出现；桌面可从 48–56 px 顶栏、216–280 px 侧栏开始，用真实内容定最小工作宽度。 | 先折叠低频面板；窄屏可以先呈现内容，再按需打开工具或详情。保留能完成的主任务。某项精确编辑若确实依赖宽屏，说明可用范围并给只读、简化操作或其他明确入口。 |
| 多项比对、审批、批处理 | 用列表—详情或带筛选的表格，高频动作与选择范围相邻；见 [业务界面](product-ui.md)。 | 保留筛选、选中和返回位置。必须二维比较时让工作区内滚动，并使操作和当前对象可辨。 |
| 图片、视频或地图 | 媒体占主区，浮动工具只承载当前任务；若采用 [轻透导航](presets/glass.md)，表单与状态使用稳定实底。 | 用不同亮度的媒体验证工具与文字、裁切和缩放；触控反馈、可见退出和键盘替代按任务提供。 |

- 色彩与组件沿用产品系统；新界面按 [外部设计 Skill 调用](external-design.md) 选产品界面的设计方法。工具界面优先让内容易扫读、反馈易察觉。表现性的材质和动效有实际任务时采用。
- 编辑器的快捷键是补充；保留可见操作，避免全局快捷键在输入框里抢键。验证删除、撤销、保存失败、重试和离开时的未保存状态，按实际功能选。面板展开与收起不应清掉选中对象。
- 先画一个包含最长名称、真实输入和代表结果的工作状态。验收走一次主流程及最重要的失败或返回分支，检查布局变化时焦点、状态和主操作是否仍可达。
