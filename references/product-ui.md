# 业务界面：SaaS、后台与操作台

先写用户打开页面要做的事：发现问题、比对、编辑、审批，还是监控。它决定信息顺序和默认密度，不套营销首屏。

| 模式 | 何时用 | 行为契约 |
|---|---|---|
| 应用外壳 + 工作区 | 高频切换同级模块 | 当前模块明显；导航、面包屑与页面标题不重复堆叠；窄屏改可达菜单或合适的移动导航 |
| 列表—详情 | 频繁筛选并查看单项 | 宽屏可双栏，窄屏切页；回列表保留查询、筛选、滚动与合理焦点；可分享的视图状态适合进 URL，敏感值不放 URL |
| 数据表格 | 精确跨行/列比较、排序、批处理 | 明确列单位、排序状态及选择范围（本页/当前筛选全部）；批量操作入口与已选数绑定；危险动作说明影响，可撤销时优先提供撤销 |
| Dashboard | 快速监控异常、做比较或解释结论 | 按 [看板与图表](data-viz.md) 选信息结构。工作型看板把异常和时间范围放在可行动的位置，再给明细；解释范围、更新时间及影响 |
| 设置/编辑 | 配置、个人资料或多角色管理 | 按用户意图分组；明确即时保存还是主动保存；有未保存改动时交代退出后果；只读、无权限、加载失败不是同一种空态 |

- 默认状态能开始任务；无数据告诉用户如何创建，筛选无匹配给清空入口，加载失败给重试。后台权限以服务为准，界面隐藏或禁用不是鉴权；能告诉用户为什么看不到、去哪里申请时提供下一步。
- 优先复用现有组件。只读表用真实表格语义；只有需类电子表格导航/编辑时才采用交互式 grid，并遵守其键盘模式。窄屏保留关键字段和主要操作；必须二维比较的表格可在标记清楚的局部区域横滚，不让整页溢出。
- 表格、侧栏和固定工具栏实测长名称、空/错、分页、筛选+排序组合、选择范围或回退状态。动态图表与数字不应替代用户的操作入口。

高保真先定一张工作屏的对齐线和密度：把异常、时间范围和下一步操作放在可扫读位置；不要把所有数字平摊成一样大的卡片。对比「紧凑表 + 侧栏详情」和「任务聚焦 + 扩展数据」，用真实长标题、选择状态和返回路径决定，而不是换色比较。

重复行共用固定的信息顺序；标签、目录、更新时间等元数据只在能影响判断时显示。同一模式下，时间顺序和按名称排序的用途分别说明。用一个实际非默认状态检查密度，例如筛选无匹配、超长名称或缺少可选字段。
